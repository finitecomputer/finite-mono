## Fail-closed cutover controls

- Release tag and manual-dispatch publication remains disabled unless Depot
  variable `FINITE_RELEASE_PUBLISH_ENABLED` is exactly `true`. Shadow tag runs
  can therefore exercise build/event behavior without touching public Releases.
- Release archives normalize tar metadata, and an alias-only path reuses and
  re-verifies existing immutable versioned assets. It does not rebuild a prior
  version to roll the rolling alias back.
- Image workflows first save one Depot result, publish a run-scoped `canary-*`
  tag, compare the Depot and GHCR digests, inspect the linux/amd64 manifest and
  provenance attestation, and pull the digest after `docker logout ghcr.io`.
- Production image tags remain disabled unless the dispatch explicitly requests
  them and Depot variable `FINITE_GHCR_PRODUCTION_PUBLISH_ENABLED` is exactly
  `true`.
- The first authenticated publisher and rollback canaries are still pending;
  the new controls have local contract coverage but are not claimed as external
  cutover evidence.
