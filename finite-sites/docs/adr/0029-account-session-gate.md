# ADR 0029: One account session, one viewer gate

Status: accepted for the locally prepared Sites v2 cutover, 2026-09-08.
Deployment and live WorkOS acceptance remain gated by `infra/runbooks/deploy-sites.md`.

## Decision

An existing finite.computer account session must open an email-authorized Site
without another email challenge, both through a direct URL and an embedded
preview. Sites remains the authority for permissions. Public sites remain public.

The standalone `finite-gated` daemon signs a short-lived, exact-origin email
vouch. Its `/authorize` route sends the browser to the configured account route.
The account route validates the existing account session and calls the gate's
`/vouch` endpoint with a server-only bearer credential and verified email.
Anonymous visitors use the account boundary's ordinary WorkOS login. No Agent,
subscription, or provisioned Finite account resource is required to view a share.
Sites verifies the signature offline and mints its existing host-scoped cookie;
its email share/publisher tables are checked again on each content request.

The dashboard preview invokes that same account-to-gate call before loading the
redemption URL into its iframe. This avoids running an interactive login inside
a sandboxed cross-site frame. The existing partitioned viewer cookie is retained.
Direct visits instead navigate Sites -> gate -> account -> Sites.

The gate has no second WorkOS integration, login cookie, account database,
membership policy, or permission cache. This replaces the original #803
assumption that independent WorkOS clients and cookies guarantee silent SSO.
Self-hosters can configure a different account boundary and gate key; Sites
still consumes the same bounded proof and owns the same authorization decision.

## Existing state and deployment

The target domain is `finite.site`, superseding ADR 0028's temporary
`v2.finite.chat` domain. The control/Git origin is `https://finite.site`,
Sites use `https://{name}.finite.site`, and the gate uses `https://auth.finite.site`.
A host-only cookie does not move between domains. Reauthentication supplies the
same email and the preserved permission rows determine access. The migration
copies the complete Recovery Set, including stable Site IDs, shares and
publisher email principals; it does not recreate grants from account membership.

Viewer magic-link and native-session endpoints are removed from the v2 daemon.
CLI actor email proofs and the hosted requester assertion for publishing remain.
Outstanding old login URLs cannot authenticate on v2. Their obsolete storage
schema remains for existing shape-migration compatibility, without live mint or
redeem paths; no token-table purge is part of this change.

The canonical server and runtime CLI remain pinned to v0.5.3 until cutover.
Legacy dashboard/native clients remain for that deployment, with a removal
condition in the technical debt ledger. New `finite.site` previews use only the
gate. This is one bounded release transition, not daemon auth-mode negotiation.
Bare npub-only grants are preserved as data but are not converted into email
grants; browser npub identity is outside this email-first slice.

## Proof and remaining acceptance

The old-writer fixture in `tests/fixtures/legacy-email-v053` was generated by the
actual deployed revision. Candidate tests cover preserved bytes, IDs, publisher
and recipient access, denial, and revocation after restart. HTTP tests cover
vouch origin/expiry/replay rejection and current permission enforcement.
Account-adapter tests reject unverified and caller-header identities.

Before cutover, test real WorkOS session refresh, logout/account switching,
external viewer login, and browser cookie policies on the final HTTPS domains.
The gate keeps no session that can outlive dashboard logout; already-issued Site
cookies retain their existing bounded lifetime and local permission checks.
